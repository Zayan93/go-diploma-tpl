# GopherMart API

В данной директории содержится код накопительной системы лояльности, который компилируется в бинарное приложение.

## Описание API

GopherMart - это REST API сервис для системы лояльности с поддержкой аутентификации пользователей.

## Запуск сервера

```bash
go run main.go
```

### Параметры запуска

Сервер поддерживает следующие параметры командной строки:

- `-a` - адрес HTTP сервера (по умолчанию: localhost:8080)
- `-b` - базовый URL для ссылок (по умолчанию: http://localhost:8080)
- `-l` - уровень логирования (по умолчанию: info)
- `-f` - путь к файлу хранения (по умолчанию: ./storage.txt)
- `-d` - строка подключения к базе данных PostgreSQL

### Переменные окружения

Также поддерживаются переменные окружения:

- `SERVER_ADDRESS` - адрес сервера
- `BASE_URL` - базовый URL
- `LOG_LEVEL` - уровень логирования
- `FILE_STORAGE_PATH` - путь к файлу хранения
- `DATABASE_DSN` - строка подключения к БД

## Эндпоинты API

### 1. Регистрация пользователя

**POST** `/api/user/register`

Регистрирует нового пользователя в системе.

#### Тело запроса (JSON):
```json
{
  "login": "user@example.com",
  "password": "password123"
}
```

#### Ответы:
- **200 OK** - пользователь успешно зарегистрирован
- **400 Bad Request** - неверный формат запроса или пустые поля
- **409 Conflict** - пользователь с таким логином уже существует
- **500 Internal Server Error** - внутренняя ошибка сервера

#### Особенности:
- Пароль автоматически хешируется с использованием SHA-256
- После успешной регистрации устанавливается сессионная кука
- Сессия действительна 24 часа

### 2. Аутентификация пользователя

**POST** `/api/user/login`

Аутентифицирует существующего пользователя.

#### Тело запроса (JSON):
```json
{
  "login": "user@example.com",
  "password": "password123"
}
```

#### Ответы:
- **200 OK** - пользователь успешно аутентифицирован
- **400 Bad Request** - неверный формат запроса или пустые поля
- **401 Unauthorized** - неверный логин или пароль
- **500 Internal Server Error** - внутренняя ошибка сервера

#### Особенности:
- После успешной аутентификации устанавливается сессионная кука
- Сессия действительна 24 часа
- Пароль проверяется по хешу

### 3. Загрузка номера заказа

**POST** `/api/user/orders`

Загружает номер заказа в систему лояльности.

#### Тело запроса:
```
Content-Type: text/plain

12345678903
```

#### Ответы:
- **200 OK** - номер заказа уже был загружен этим пользователем
- **202 Accepted** - новый номер заказа принят в обработку
- **400 Bad Request** - неверный формат запроса
- **401 Unauthorized** - пользователь не аутентифицирован
- **409 Conflict** - номер заказа уже был загружен другим пользователем
- **422 Unprocessable Entity** - неверный формат номера заказа
- **500 Internal Server Error** - внутренняя ошибка сервера

#### Особенности:
- Номер заказа должен состоять только из цифр
- Заказы автоматически получают статус "NEW"
- Поддерживается проверка дублирования заказов
- Требуется аутентификация пользователя

### 4. Получение списка заказов

**GET** `/api/user/orders`

Возвращает список всех заказов пользователя.

#### Ответы:
- **200 OK** - список заказов успешно получен
- **401 Unauthorized** - пользователь не аутентифицирован
- **500 Internal Server Error** - внутренняя ошибка сервера

#### Формат ответа (JSON):
```json
[
    {
        "number": "9278923470",
        "status": "PROCESSED",
        "accrual": 500,
        "uploaded_at": "2020-12-10T15:15:45+03:00"
    },
    {
        "number": "12345678903",
        "status": "NEW",
        "uploaded_at": "2020-12-10T12:00:00+03:00"
    }
]
```

#### Особенности:
- Заказы отсортированы по времени загрузки (от новых к старым)
- Формат даты соответствует RFC3339
- Поле `accrual` присутствует только для обработанных заказов
- Требуется аутентификация пользователя

## Хендлеры

### Handler

Основная структура для обработки HTTP запросов.

#### Методы:

- **PostRegister** - обработка регистрации пользователей
- **PostLogin** - обработка аутентификации пользователей
- **PostOrders** - обработка загрузки номеров заказов
- **GetOrders** - получение списка заказов пользователя
- **PostShorten** - заглушка для сокращения URL (не реализована)

#### Функции безопасности:

- **hashPassword()** - хеширование паролей с использованием SHA-256
- **generateSessionID()** - генерация уникальных идентификаторов сессий
- **setAuthCookie()** - установка аутентификационных куки

## Middleware

Сервер использует следующие middleware:

- **GzipMiddleware** - сжатие ответов с использованием gzip
- **WithLogging** - логирование всех HTTP запросов

## Хранение данных

### Поддерживаемые бэкенды:

1. **PostgreSQL** (основной)
   - Автоматическое подключение при указании `DATABASE_DSN`
   - Схема: 
     - Таблица `users` с полями: id, login, password, created_at
     - Таблица `orders` с полями: id, user_id, order_num, status, created_at, updated_at
       - Статусы заказов: NEW, PROCESSING, INVALID, PROCESSED
       - Связь с пользователями через user_id (внешний ключ)

2. **Файловое хранение** (резервный)
   - Используется при недоступности PostgreSQL
   - Путь настраивается через `FILE_STORAGE_PATH`

## Безопасность

- Пароли хешируются с использованием SHA-256
- Сессионные куки имеют флаг HttpOnly
- Поддержка SameSite для защиты от CSRF атак
- Автоматическое истечение сессий через 24 часа

## Логирование

Сервер использует структурированное логирование с помощью zap:

- Уровень логирования настраивается через параметр `-l` или `LOG_LEVEL`
- Логируются все HTTP запросы
- Ошибки аутентификации и регистрации
- Подключения к базе данных

## Примеры использования

### Регистрация нового пользователя:
```bash
curl -X POST http://localhost:8080/api/user/register \
  -H "Content-Type: application/json" \
  -d '{"login": "test@example.com", "password": "secret123"}'
```

### Аутентификация пользователя:
```bash
curl -X POST http://localhost:8080/api/user/login \
  -H "Content-Type: application/json" \
  -d '{"login": "test@example.com", "password": "secret123"}'
```

### Загрузка номера заказа:
```bash
curl -X POST http://localhost:8080/api/user/orders \
  -H "Content-Type: text/plain" \
  -b "session_id=your_session_cookie" \
  -d "12345678903"
```

### Получение списка заказов:
```bash
curl -X GET http://localhost:8080/api/user/orders \
  -b "session_id=your_session_cookie"
```
